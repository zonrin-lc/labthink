# 行业解决方案 PPT 制作

面向"企业材料 → 行业解决方案 PPT"的完整工作流。核心顺序：**判定工作模式 → 读全材料 → 内容稿先行 → 事实审查 → 修订定稿 → 成稿幻灯片 → 交付**。禁止跳过内容稿直接做PPT，禁止凭印象写数据。

## 0. 工作模式判定（开工前第一步）

根据是否存在可复用的定稿模板，选择工作模式：

| 模式 | 适用场景 | 核心动作 |
|---|---|---|
| **模式A：模板复用（默认）** | 基于已有的医药行业方案PPT（V1.5定稿，32页，元素已解组优化布局）扩展到食品、化工、环境、建材等其他行业 | 只重写行业专属页（约25%），通用模块直接复用版式与内容，半通用模块替换行业要素 |
| **模式B：从零创作** | 无可用模板、或用户明确要求全新结构、或目标行业与模板差异过大（如非重量分析产品线） | 按"读全材料→内容稿→事实审查→PPT"完整流程从零搭建 |

**判定规则**：用户提到"基于已有方案""参考医药版""其他行业也出一份""按这个模板改"等表述时，一律走模式A；用户提供全新材料且未提及模板时，走模式B。两种模式共享行业知识路由、术语规范、事实审查和文案规范。

## 0.1 模板复用矩阵（模式A核心 · 32页拆解）

医药行业定稿PPT共32页，按复用程度分三类。做任何其他行业PPT前，先对照本表确认每页的处理方式，禁止全篇重写。

**基础模板文件**：`assets/templates/pharma-template-v1.6.pptx`（skill内置，32页）
- V1.6为最新定稿版：C860/C870场景页各补充第二个真实客户案例（参照C840双案例布局），元素已解组优化布局
- V1.5已弃用（场景页仅单案例）；V1.4已弃用（元素组合导致布局问题）
- 做其他行业方案时，复制此文件到工作目录，导入为飞书Slides后逐页修改

|---|---|---|---|

| | 15,17,19 | C840/C860/C870三款产品详情页 | 复用产品实拍图和参数表；技术特点描述不变 |

| | 16,18,20 | C840/C860/C870工作流程页 | 复用流程图骨架；流程节点中的温度、时长、恒重判定参数替换为目标行业标准规定值 |

| | 4 | 传统检测四重困境 | **必须重写**：替换为目标行业特有的人工检测痛点（效率/误差/风险/合规四维度） |
| | 5 | 政策驱动页 | **必须重写**：替换为目标行业的监管政策、新标准实施、数智化转型驱动，每条标注来源 |
| | 25 | 应用场景与实证章节页 | 复用版式，替换章节标题 |
| | 26 | 场景一·C840（蒸发残渣/不挥发物/总迁移量） | **必须重写**：目标行业C840对应标准+真实检测案例（或标准方法示例） |
| | 27 | 场景二·C860（炽灼残渣/灰分/烧失量） | **必须重写**：目标行业C860对应标准+真实检测案例 |

**关键结论**：模式A下，每份新行业PPT真正需要从零撰写的只有 **P4困境 + P5政策 + P26-28三个应用场景** 共5页核心内容，其余27页在模板基础上微调即可。

### 标准表使用注意

- 标准表中有6条标注"与恒重分析无关，疑似误放"（如GB/T 32723、GB/T 35834等），生成PPT时**必须剔除**，不得引用。
- 部分标准为"征求意见稿"或"即将实施"状态（如GB/T 23951修订、GB/T 5486-2026），政策页可突出"新标准即将实施，提前布局自动化"作为卖点，但必须明确标注状态。
- 标准号以官方题录为准，商业网站标注的"新版号"不可靠（如网上流传"GB/T 508-2016"实为不存在版本，现行版是1985）。

## 0.3 行业推进策略（多行业批量扩展时参考）

当用户需要批量出多个行业PPT时，按"标准成熟度 × 案例丰富度 × 市场优先级"分三批推进，避免在素材不足的行业上浪费时间。

| 批次 | 行业 | 标准覆盖 | 现有案例 | 推荐理由 |
|---|---|---|---|---|
| **第一批** | 食品·食品接触材料·包装 | C840●●● C860● C870● | 白酒固形物1例 | 标准体系最完整（GB 4806/GB 31604/GB 5009），C840总迁移量是核心场景 |
| **第一批** | 化工·化学试剂·有机无机化工 | C840●●● C860●●● C870● | 无 | 三款产品全覆盖（GB/T 9740/9741/6284），标准体系成熟 |
| **第二批** | 环境监测·水质·大气·土壤·固废 | C840● C860● C870●●● | 无 | 政策驱动强（HJ系列），C870颗粒物/水分场景突出 |
| **第二批** | 涂料·胶粘剂·塑料·橡胶·日化 | C840●●● C860●● — | 聚乙烯管1例 | C840不挥发物是核心（GB/T 1725/2793），胶粘剂2026新标可做卖点 |
| **第二批** | 建材·水泥·陶瓷·玻璃·铸造 | — C860●● C870● | 无 | 水泥烧失量（GB/T 176-2025新标）、绝热制品含水率 |
| **第三批** | 冶金·钢铁·有色·矿石·耐火材料 | — C860●●● C870● | 无 | 高温灼烧场景（800℃+），客户偏B端大宗 |
| **第三批** | 煤炭·焦炭·固体燃料 | — C860● C870● | 无 | 工业分析三项目联动（水分/灰分/挥发分） |
| **第三批** | 造纸·纸浆·纺织·皮革·木材 | — C860● C870●●● | 无 | 含水率/回潮率是C870强项 |
| **第三批** | 饲料·肥料·农药 | — C860● C870● | 无 | 水分/粗灰分常规检测 |

> 医药行业是模板本身，不在扩展清单内。单行业任务不适用本策略，直接做用户指定的行业。

## 0.4 案例缺口降级策略（模式A必看）

检测报告库目前约80%案例集中在医药行业，非医药行业做PPT时应用场景页可能缺真实客户案例。按以下优先级降级处理，**禁止编造客户和数据**：

| 优先级 | 处理方式 | 适用条件 |
|---|---|---|
| 1 | 使用该行业真实检测报告 | 检测报告库中有该行业报告（如食品行业有白酒固形物报告） |
| 2 | 使用"标准方法 + 模拟检测流程" | 无真实案例，但行业标准完整：按标准方法描述检测流程，标注"标准方法示例，数据待实测"，不编造具体数值 |
| 3 | 使用跨行业类比案例 + 明确标注 | 无同行业案例，但有相近行业案例：如做塑料行业时引用"高密度聚乙烯管炽灼残渣"案例（来自质检院），标注"同类材料检测参考" |
| 4 | 改为"应用领域矩阵"页 | **仅适用于P26-28场景页**：完全无案例时，将三个场景页合并为一页，展示该行业C840/C860/C870分别适用的检测对象、标准号、典型样品，不出现具体客户数据 |

降级处理后，在内容稿和PPT备注中明确标注"本页为标准方法示例/应用领域说明，非真实客户案例"，交付时向用户说明该行业案例缺口，建议后续补充实测数据。

> **重要：P9客户墙不适用降级策略**。客户墙必须使用真实客户logo，必须询问用户提供客户名单，禁止改为应用领域矩阵或其他替代形式。详见0.5节。

## 0.5 客户墙制作子流程（P9页 · 半通用模块 · 必须用真实客户logo）

P9"行业服务客户"页是半通用模块：医药行业有现成的49家企业logo资产可直接用；其他行业需要按目标行业客户名单重新抓取和排版。**客户墙必须使用真实客户logo，禁止改为应用领域矩阵或其他替代形式。无客户名单时必须主动询问用户提供，不得自行降级。**

本skill内置完整的logo墙制作工具链（`scripts/logo-wall/`），覆盖从官网抓取到PPT生成的全流程。

### 开工前必须做的事

**做任何非医药行业的客户墙之前，必须先向用户询问客户名单**：
- 询问话术："P9客户墙需要49家该行业的典型客户企业名称和官网，用于制作logo墙。请提供客户名单（一行一家企业，包含企业全称和官网URL），我会按名单顺序抓取logo并排版。"
- 用户提供名单后，按以下6阶段流程制作
- 用户暂时无法提供名单时，**暂停P9制作**，其他页面继续，待用户提供名单后再补做P9
- **禁止**在未获得用户名单的情况下，自行编造客户名单或改为应用领域矩阵

### 内置资产（医药行业直接可用）

- `assets/logo-wall/logos/01_…png … 49_…png` — 49家医药企业logo，已QA通过（白底/透明底彩色版，统一裁边+fit-inside）
- `assets/logo-wall/template.pptx` — 医药行业客户墙模板（16:9，标题"医药行业服务客户——1000+制药企业的共同选择"，49个1.36″×0.52″圆角单元格）
- `assets/logo-wall/order.txt` — 49家企业排序文件（严格按用户名单顺序，不可重排）
- `assets/logo-wall/logo-index.xlsx` — logo索引表（企业名→文件名→来源→备注）

医药行业PPT的P9页可直接用 `refill_template.py` 一键重建：
```bash
python scripts/logo-wall/normalize_logos.py assets/logo-wall/logos --outdir logos_fit --maxw 1200 --maxh 400
python scripts/logo-wall/refill_template.py assets/logo-wall/template.pptx logos_fit assets/logo-wall/order.txt 客户Logo墙.pptx
```

### 其他行业客户墙制作（6阶段）

当目标行业不是医药、或用户提供了新的客户名单时，按以下流程制作。**前提是已获得用户提供的客户名单，未获得名单时不得开始制作。**

**Phase 0 — 准备客户名单**
- 一行一家企业：`name,official_url1,official_url2,...`（CSV格式）
- 核实官网域名，避免"错名陷阱"（如"仲景皖西"应为"仲景宛西"）和"错域名陷阱"（相似域名可能属于不同公司）
- 子公司无独立官网时用母公司品牌logo并注明

**Phase 1 — 批量抓取（无浏览器）**
```bash
python scripts/logo-wall/fetch_logos.py companies.csv --outdir logos_raw
```
通常成功率50-70%，失败的进入Phase 2。

**Phase 2 — 浏览器抓取（Playwright headless Chromium）**
```bash
pip install playwright && python -m playwright install chromium
python scripts/logo-wall/browser_fetch.py remaining.csv --outdir logos_raw
```
可处理JS渲染站点、WAF拦截、cookie弹窗等。

**Phase 3 — SVG转PNG**
```bash
python scripts/logo-wall/svg_to_png.py logos_raw
```

**Phase 4 — 视觉QA（必须逐张检查）**
```bash
python scripts/logo-wall/make_sheet.py logos_raw sheet.png
```
打开拼图逐张核对：不可见（白标透明底）→重着色；错公司→重抓；深色底块+白标→换彩色版或重着色；裁切不全→重截；模糊→3x重抓；含股票代码/电话等杂物→裁掉。

**Phase 5 — 标准化**
```bash
python scripts/logo-wall/normalize_logos.py logos_raw --outdir logos_fit --maxw 1200 --maxh 400
```
自动裁白边、统一外接框（fit-inside，保持纵横比）、可选重着色和视觉重量微调（方形/实心标缩至0.85-0.9，细长标可放大至1.0）。

**Phase 6 — 生成PPT客户墙**
两种模式：
- **模式A（推荐）**：用户有自己的模板PPT时，用 `refill_template.py` 只替换logo图片，保留模板的标题、单元格和装饰：
  ```bash
  python scripts/logo-wall/refill_template.py template.pptx logos_fit order.txt out.pptx --cellw 1.36 --cellh 0.52 --pad 0.06
  ```
- **模式B**：无模板时从零构建：
  ```bash
  python scripts/logo-wall/build_logo_wall.py logos_fit order.txt out.pptx --title "..." --cols 7 --cellw 1.36 --cellh 0.52
  ```

### 客户墙设计铁律（不可违反）

1. **严格按名单顺序排列**，不按颜色/大小/重要性重排
2. **统一的是格子，不是logo尺寸**——fit-inside保持纵横比，禁止拉伸
3. **底色统一**：白底/透明底彩色版；"深色底块+白标"一律不用，改为重着色为品牌色
4. **数量=名单数量**，不凑整、不增减（如49家就49个格子，哪怕网格不是完美矩形）
5. **必须做视觉QA**，自动化抓取经常返回错公司、不可见白标、裁切不全
6. **客户名模糊化**：PPT中只展示logo，正文/讲稿中用"某大型XX企业"等模糊表述（见copywriting.md）

详细设计原则见 `references/logo-wall-design.md`，实战踩坑排错见 `references/logo-wall-troubleshooting.md`。

## 0.6 行业知识路由（开工前加载）

1. 识别本次目标行业与检测项目（产品线三系列：C870 干燥失重/水分、C860 灼烧残渣/灰分、C840 蒸发残渣/不挥发物）。
2. 从 `references/industry/` 加载对应行业知识文件（每个文件内含"产品映射表"：检测项目 → 产品线 → 标准）：
   - `pharma-knowledge.md`（医药/药包材/制药用水）
   - `food-knowledge.md`（食品 + 食品接触材料）
   - `environment-knowledge.md`（环境监测/水质/大气/土壤/固废/海洋）
   - `metallurgy-knowledge.md`（冶金/钢铁/有色金属/矿石/耐火材料）
   - `construction-knowledge.md`（建材/水泥/陶瓷/玻璃/铸造）
   - `rubber-knowledge.md`（橡胶）
   - `plastics-knowledge.md`（塑料及高分子）
   - `chemical-knowledge.md`（化学试剂/化工/涂料/胶粘剂/油墨）
   - `tobacco-knowledge.md`（烟草）
   - `feed-knowledge.md`（饲料/肥料/农药）
   - `paper-knowledge.md`（造纸/纸浆/纺织/皮革/木材）
   - `energy-knowledge.md`（煤炭/石油/润滑油）
3. 需要标准原文/核对标准号时，查标准库 `D:\兰光\行业标准\`（十大领域目录，含已下载PDF与README核对清单）；标准全文公开系统 https://openstd.samr.gov.cn/bzgk/gb/ 可在线读取强制性国标全文。
4. 无对应文件时：用 `scripts/scan_keywords.py` 从企业材料中提取该行业的标准号、规范术语、客户类型与易错点，现场建立知识清单后再开工；无法核实的条目标注"待核验"，后续沉淀为新知识文件加入 `references/industry/`。
5. 行业知识文件只放行业专属信息（术语规范、标准映射、易错点、客户类型、政策来源）；通用流程一律留在本文件，避免重复。标准号以现行有效版本为准（注意区分新版/旧版，如 GB/T 4498.1-2025、GB/T 2793-2026 均已换版；标准号以官方题录为准，商业网站"新版号"不可靠，如网上流传的 GB/T 508-2016 实为不存在版本，现行版是 1985）。

## 0.7 行业术语规范（重点 · 每轮必做）

同一项检测在不同行业有完全不同的标准术语（如"干燥失重/水分/干燥减量法"、"炽灼残渣/灰分/粗灰分/烧失量"），这是内容稿和演讲中**最高频的出错点**。规则：

1. **开工即查**：加载行业知识文件的同时，打开 `references/industry/terms-crosswalk.md` 跨行业术语对照表，确认本次客户行业的标准用词。
2. **写前核对**：内容稿、PPT 正文、串讲词中每个检测项目术语，都按对照表选用客户所属行业的说法；禁止把医药"炽灼残渣"写成"灼烧残渣"、把食品接触材料"总迁移量"写成"蒸发残渣"、把饲料"粗灰分"省略"粗"字等。
3. **方向分清**："灼烧残渣/灰分"测剩余物，"灼烧减量/烧失量/灼烧损失量"测失去质量，两者不可互换。
4. **参数对号**：灰分灼烧温度因标准而异（食品550℃、石油775℃、橡胶800℃、造纸575/900℃），引标准条款时温度必须与标准号匹配。
5. **审查环节复检**：事实审查时把术语作为独立检查项逐条过一遍，与事实错误同级别对待。

## 0.8 模板复用实操避坑指南（模式A必看 · 沉淀自食品行业实战）

模式A下，从医药PPT扩展到其他行业时，以下是最高频的出错点和对应的解决方案。**每做一个新行业都要逐条过一遍**，不要凭记忆操作。

### 0.8.1 产品名称不可改原则（最高频出错点）

兰光三系列产品的**官方名称是固定的**，跨行业做方案时**绝对不能改**：

| 产品线 | 官方产品名称（不可改） | 跨行业检测项目术语（可改） |
|---|---|---|
| C840 | 集成式**蒸发残渣**检测系统 | 食品→总迁移量；化工→蒸发残渣/不挥发物；药包材→不挥发物 |
| C860 | 集成式**灼烧残渣**检测系统 | 食品→灰分；橡胶/塑料→灰分；水泥→烧失量；饲料→粗灰分 |
| C870 | 集成式**干燥失重**检测系统 | 食品→水分；化工→干燥减量法；造纸→分析试样水分；化纤→回潮率 |

**规则**：
- 页面标题、产品实拍图说明、参数表中的产品名称 → **保留原样**
- "参照XX标准""适用对象""应用场景""检测项目"描述 → **按目标行业术语替换**
- 工作流程页的流程节点名称（如"蒸发残渣检测"）→ 可改为行业术语（如"总迁移量检测"），但页面标题中的产品名称保留

**反面案例**（食品行业实战中犯过的错）：把P16标题写成"集成式总迁移量检测系统-C840 工作流程"——产品名称被误改，必须改回"集成式蒸发残渣检测系统"。

### 0.8.2 PPT内容与备注必须同时修改

飞书Slides的每页包含两部分：**可见的PPT内容**（shape/text/table）和**演讲者备注**（`<note>`元素）。两者是独立的文本块，修改时必须同步：

- 只改PPT内容不改备注 → 演讲时念到医药行业内容
- 只改备注不改PPT内容 → 页面显示医药行业标准

**检查方法**：修改完每页后，用 `xml_inspect.py` 或回读XML，同时检查 `text_preview` 和 `note_preview` 两个字段。

**高频遗漏页**：
- P5政策页：PPT三列卡片改了，但备注大段文字还是医药的（新药典/集采/医药工业数智化）
- P4困境页：四个卡片改了，但备注中的温度参数（700-800℃/浓硫酸）还是医药的
- P12产品总览：PPT标准引用改了，但备注还是"参照药典通则0831"
- P15/17/19产品详情：PPT适用对象改了，但备注还是"系列是药包材/药品检测的自动化专家"

### 0.8.3 span拆分导致的替换不完整（必须多轮验证）

从PPTX导入飞书Slides后，同一句话经常被拆分成多个 `<span>` 元素（因为字体、颜色、大小不同）。例如：

```xml
<span>2025</span><span color="...">版中国药典四部凡例</span>
```

直接用字符串替换 `"2025版中国药典四部凡例"` 会**匹配失败**，因为中间隔着span标签。

**解决方案**：
1. **第一轮**：用普通字符串替换能匹配的部分
2. **回读XML**：用关键词扫描（药典/YBB/0831/制药/药包材等）定位残留
3. **第二轮**：用正则表达式忽略span标签，例如：
   ```python
   re.sub(r'2025</span><span[^>]*>版中国药典四部凡例', 'GB 5009.3/5009.4恒重要求', xml)
   re.sub(r'0831</span><span[^>]*>干燥失重', 'GB 5009.3水分', xml)
   ```
4. **再次回读验证**：确认所有残留已清除

**实战经验**：食品行业PPT经过了3轮替换+验证才彻底清除所有医药术语残留。不要指望一次替换完成。

### 0.8.4 客户墙必须用真实客户logo（P9 · 禁止降级）

P9客户墙**必须使用真实客户logo**，禁止改为应用领域矩阵或其他替代形式。

- 做非医药行业方案时，**必须先询问用户提供49家客户名单**（企业全称+官网URL）
- 用户提供名单后，按0.5节6阶段流程制作（名单→抓取→SVG转PNG→视觉QA→标准化→生成PPT）
- 用户暂时无法提供名单时，**暂停P9制作**，其他页面继续，待用户提供名单后再补做
- **禁止**自行编造客户名单、禁止用应用领域矩阵替代、禁止用医药行业logo充数

### 0.8.5 合规页跨行业适用性（P23）

P23"数据合规"页中的法规名称，跨行业时按以下规则处理：

| 法规/标准 | 医药 | 食品 | 化工 | 处理方式 |
|---|---|---|---|---|
| GMP | 药品GMP | 食品GMP（同样适用） | 不强制 | 食品行业保留，增加HACCP；化工行业删除或改为"质量管理体系" |
| 21 CFR Part 11 | 核心要求 | 出口企业选配 | 出口企业选配 | 保留但标注"出口企业选配"，不要删除 |
| ALCOA原则 | 核心 | 适用 | 适用 | 通用，保留 |
| HACCP | 不涉及 | **核心** | 不涉及 | 食品行业必须增加 |

**规则**：不要一刀切删除所有医药法规，先判断目标行业是否适用。GMP在食品行业同样存在（食品生产质量管理规范），21 CFR Part 11是美国FDA电子记录要求，出口企业都可能需要。

### 0.8.6 Windows平台实操注意事项

- `lark-cli` 的 `--output`/`--file`/`--input` 只接受**CWD内相对路径**，传绝对路径会被拒；开工第一步先 `cd` 到工作目录
- `python -c "..."` 中含双引号转义会报 `SyntaxError`，复杂逻辑一律 `Write` 到 `.py` 文件再执行
- `lark-cli drive +export` 的参数是 `--doc-type` 和 `--file-extension`，不是 `--type` 和 `--extension`
- 批量写入多页时，用Python脚本循环调用 `lark-cli`，不要在PowerShell中用 `&&` 串联（PS不支持）
- 导入PPTX后，用 `+update-slide` 整页覆盖是最高效的修改方式（比 `+replace-slide` 块级替换更简单，适合整页内容替换）

### 0.8.7 标准引用替换清单（每页必查）

以下位置在每个行业方案中都需要替换标准引用，**逐页核对不要遗漏**：

| 页面 | 标准引用位置 |
|---|---|
| P11 产品总览 | 三个产品卡片下方的"参照XX标准" |
| P12 产品系列总览 | PPT内容 + 备注中都有标准引用 |
| P15 C840详情 | 标题下方标准标签 + "合规刚性要求" + 备注 |

### 0.8.8 autoFit属性设置（布局溢出的根因 · 新发现）

PPTX导入飞书Slides后，文本框的`autoFit`属性默认为`shape-auto-fit`（根据形状大小缩小文字）。当替换为更长的行业术语时，会导致**文字溢出或超框**。必须检查并修改以下位置：

| 页面 | 元素 | 原autoFit | 应改为 | 原因 |
|---|---|---|---|---|
| P12 产品系列总览 | C840/C860/C870上方的标准引用标签 | shape-auto-fit | text-auto-fit | 标准号长度不同（如"GB 31604.8-2021 · GB 4806系列总迁移量"比原药典引用长） |
| P14/P16/P18 产品详情 | 适用对象的4个标签 | shape-auto-fit | text-auto-fit | 行业适用对象术语长度不同（如"酸性/醇性食品模拟物"比"注射用水"长） |

**修改方法**：在XML中找到对应`<shape>`的`<content>`元素，将`autoFit="shape-auto-fit"`改为`autoFit="text-auto-fit"`。

**判断方法**：用户反馈"文字超出框了"、"样式不对"、"需要根据文字内容调整形状大小"时，首先检查autoFit属性。

### 0.8.9 各页面替换清单（模式A必做 · 逐页核对）

以下是每个高频出错页面的**完整替换清单**，做新行业时逐条核对：

#### P5 政策驱动页
- [ ] 严监管内容：集采中选品种/GMP全覆盖/15个药品→目标行业监管内容
- [ ] 信息来源：国家药监局公告→目标行业主管部门（如市场监管总局）
- [ ] 调研报告：Deloitte《Pharma's QC lab of the future》→去掉"Pharma's"
- [ ] 备注：大段政策描述同步替换

#### P14/P16/P18 产品详情页
- [ ] 合规刚性要求："不达标即不可用于药品包装"→"不达标即不可用于XX包装"
- [ ] 适用对象：中药材及饮片/有机药物/药用辅料→目标行业适用对象（3-4项）

#### P26-28 场景页（C840/C860/C870 · 双案例布局）
V1.6模板中每个场景页均为**左右双案例**布局，替换时必须两个案例同步修改：
- [ ] 左侧案例：客户名称、设备说明、表格数据（检测项目/平行1/平行2/平行3或RD值/判定）
- [ ] 右侧案例：客户名称、设备说明、表格数据（结构与左侧一致）

- [ ] 右侧引用框：总结性文字替换
- [ ] 备注：场景描述同步替换（需涵盖两个案例）
- [ ] C840场景页表格结构：5列（试样/介质/类别/残渣量/折算/限值/判定）或6列，注意两个表格结构可能不同
- [ ] C860/C870场景页表格结构：4-5列（检测项目/平行1/平行2/平行3/判定），两个表格结构一致

### 0.8.10 医药术语残留检查清单（交付前必跑）

## 工作流

### 模式A：模板复用工作流（默认 · 基于医药PPT扩展）

```
第1步：行业素材提取（从飞书素材库+本地标准库取数）
  ├─ 从行业标准表筛选目标行业所有标准 → 整理成"标准对照表"（标准号/名称/版本/对应产品/关键参数）
  ├─ 从检测报告库筛选目标行业案例 → 无案例则标记并启动降级策略（见0.4）
  ├─ 加载对应行业知识文件（references/industry/）
  └─ 联网补充：行业政策、市场规模、典型痛点（仅用于P4/P5，标注来源）

第2步：行业专属页撰写（核心工作量，共5页）
  ├─ P4 传统检测困境 → 替换为目标行业特有的人工检测痛点（效率/误差/风险/合规四维度）
  ├─ P5 政策驱动 → 替换为目标行业的监管政策/新标准实施/数智化转型，每条标注来源
  ├─ P26 场景一(C840) → 目标行业C840对应标准 + 真实案例或标准方法示例
  ├─ P27 场景二(C860) → 目标行业C860对应标准 + 真实案例或标准方法示例
  └─ P28 场景三(C870) → 目标行业C870对应标准 + 真实案例或标准方法示例

第3步：半通用模块微调（快速，共5页）
  ├─ P9 客户墙 → 医药行业直接用内置49家logo资产（refill_template.py一键重建）；
  │              其他行业按0.5节客户墙子流程抓取新logo并排版；无客户名单时改"应用领域矩阵"
  ├─ P16/18/20 工作流程 → 替换温度/时长/恒重参数为目标行业标准值
  └─ P30 实施建议 → 替换验证标准为目标行业常用规范

第4步：通用模块确认（19页，仅检查不重写）
  ├─ 封面/目录/公司介绍/资质/产品体系/产品详情/四大特点/服务支持/封底
  ├─ 仅替换封面标题行业名、合规页法规名称等关键词
  └─ 确认配色/字体/版式与模板一致（见 brand-language.md）

第5步：内容稿整合与事实审查
  ├─ 按 deck-structure.md 五幕结构整合完整内容稿
  ├─ 按 fact-check.md 逐条事实审查（重点审查行业专属页的标准号、数据、术语）
  └─ 输出审查报告，无法核实的标注"待补充"

第6步：修订定稿
  ├─ 按审查报告逐条修订
  └─ 用户确认内容稿后进入PPT制作

第7步：制作幻灯片与交付
  ├─ 读取 ppt skill，基于模板版式逐页生成（模式A优先复用模板XML结构）
  ├─ 逐页"落XML → xml_lint（error_count=0）→ 写入"闭环
  ├─ 全文回读重跑校验，截图核对渲染
  ├─ 每页 <note> 写3-5句可直接照读的讲稿
  └─ 导出PPTX + 在线链接交付
```

### 模式B：从零创作工作流（无模板时使用）

**1. 读全参考材料**
- 材料目录可能含 docx / pptx / pdf / xlsx / png。
- docx 必须同时遍历 paragraphs、tables、inline_shapes 及 word/media/ 图片；pdf 除 get_text 外还要 get_images / find_tables；pptx / xlsx 提取全部文本与图表；产品页图片、实拍图、流程图必须保留原信息。
- 公司介绍 PPT 常是数据权威来源（成立年份、客户数、资质、荣誉、研发投入），优先完整读取。
- 用 `scripts/scan_keywords.py` 按关键词（产品、客户、资质、荣誉、研发、标准等）扫描定位关键事实，命中后回到原文逐条核对。
- 所有数字、名称、结论必须可追溯到具体文件与页码，禁止凭印象或先验知识补充。

**2. 内容稿先行**
- 默认先产出内容稿（docx），用户确认后再制作幻灯片；用户明确只要文字时，只交付文字稿。
- 内容稿结构参考 `references/deck-structure.md`（默认五幕结构）；每页内容标注数据出处（文件+页码）。
- 文字稿可直接交付、可讨论修改，是后续PPT的唯一内容基线。

**3. 事实审查**
- 按 `references/fact-check.md` 的清单逐条核验内容稿；行业术语对照 `references/industry/` 对应文件。
- 输出审查报告：每条问题 = 位置 + 问题描述 + 参考材料依据（原文引用）+ 修改建议；**无法在材料中找到出处的内容单独标注**。
- 审查未发现问题也要明确说明"未发现问题"及检查范围。
- 存在多方审查意见时，逐条说明采纳/不采纳及理由。

**4. 修订定稿**
- 按审查报告逐条修订；修订后所有数据、机构名、标准号与材料一致。
- 用户对文案提出调整（分类、措辞、字数）时，直接给出可粘贴的最终文字，并说明改了什么、为什么。

**5. 制作幻灯片**
- 读取并遵循 ppt skill 的 SKILL.md 及对应分支（新建走新建流程，改稿走 slides-editing 流程），不可凭记忆操作。
- 选定设计系统后全篇遵守；逐页"落XML → xml_lint（error_count=0）→ 写入"闭环，全文回读重跑校验，截图核对渲染，导出 PPTX。
- 每页 `<note>` 写 3-5 句可直接照读的讲稿；用户索要串讲词时给出简短口播稿（100-150字）。
- 产品页优先使用产品实拍图；流程类内容用流程图页；共性特点按"精准/高效/合规/安全"等四维展开。
- 跨轮编辑后必须再次用 present_files 交付最新版本。

**6. 文案与合规规范**
- 客户视角措辞、企业客户名模糊化、属地标注、数字口径见 `references/copywriting.md`。
- 行业术语与标准条款见 `references/industry/` 对应文件，凡涉及法规/药典/国标一律核对后再写。
